## 本番連携に必要な追加実装（まだ未実装）
1. 顧客向けOTPの発行を、所有者Gmail限定テストから分離した新しいAPIにする。現在の管理者専用送信APIを転用しない。
2. 認証チャレンジを **連絡先の保護された識別子** と **申込下書きID** にサーバー側で結びつける。ブラウザの `verified=true` などのフラグを受注許可の根拠にしない。
3. 本人確認完了後も、サーバー側で再度受付スイッチ・CAPTCHA・認証有効期限・チャレンジ未使用・レート制限を判定する。
4. 認証済みチャレンジを、1件の下書き申込に対して一度だけ消費する。DBトランザクションで重複受注を防止する。
5. 顧客向け送信手段・送信者・配信失敗時の処理・個人情報保存/削除期限を確定する。
6. 一般受付OFFを維持したまま、ステージングで失敗系・権限境界・期限切れ・再利用・同時実行を検証する。

## 公開不可の条件
- 管理者用テスト画面の正常動作だけで顧客向け申込を公開しない。
- 本番DBに架空案件を作成したり、顧客メールへ試験送信したりしない。
- Square決済・既存の運転請負機能は変更しない。
- セキュリティ確認と明示的な公開判断が終わるまで `cargo_intake_control.intake_enabled=false` のまま。
