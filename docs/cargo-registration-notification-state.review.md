## 通知状態保存と排他制御

[ローカル保存の詳細](cargo-external-notification-persistence.review.md) にAPI、失敗時の扱いと保証範囲を記載。

新規のstoreはPR #5の純粋な通知状態遷移を再利用する。管理された一つのホストの非公開なローカルファイルシステム内だけで、状態を保存し、排他ロックと世代番号により複数プロセスの同時更新・二重claim・古い状態による上書きを防ぐ。ファイル同期と名前変更、ディレクトリ同期を終えるまで成功を返さない。

初期化は明示操作に限り、既存保存先を初期化し直さない。状態欠落・破損・未完了一時ファイル・残留ロック・不確実な書込は停止し、時間経過でロックを奪わない。処理開始/送達不明/失敗の記録を新しい観測で消さず、自動再claim・再送・件数リセットの経路を作らない。

保存対象は既存kernelが検証した固定コード・時刻・イベント番号・状態だけ。生の監視入力、顧客情報、通知先、秘密値、任意のエラー本文を保存・出力しない。通知先null・送信無効・dispatches=0を維持し、通信機能は持たない。

保証範囲は同じ保存先を共有する単一ホスト内の協調プロセスである。複数ホスト/独立したCI runner/ネットワークファイルシステムの分散排他、外部定期実行、通知到達、未解決の送達を人が照合する運用は今回未実装。ローカルで一回だけclaimできることを、本番で二重通知が起きないという保証へ拡張しない。
