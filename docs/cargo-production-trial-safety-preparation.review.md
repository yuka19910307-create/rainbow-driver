# 本番本人限定試験の停止中の準備

2026-10-16 UTC。今回追加したものは無効なローカル設定と読取診断だけ。本番・検証への配備、SQL変更、試験開始、実メール送信は行っていない。

## 今回実装した範囲

`integrations/cargo-safety-preparation/production-trial-policy.disabled.json` は `enabled=false` とし、本人アカウント、開始日時、試験時間、送信試行の上限、架空案件、架空見積金額・条件、実行承認をすべて `null` にしている。前回文書の「最大2通・30分」は未承認の実行提案であり、今回の既定値として採用しない。設定へ値を記入するだけでは試験を開始できない。

`scripts/check-cargo-production-trial-preflight.cjs` は、既存の本番監視SELECTと同じ形式の、手元にある結果を標準入力で読む。接続先・時刻・状態の自己申告を外部へ照会せず、個人情報を取得・表示しない。判定結果は固定コードと `execution_allowed=false` だけである。停止フラグが一致しても、未承認・未実装の阻害条件を必ず返す。正常な停止状態の診断も終了コード1、入力異常は2とする。

この診断は現時点の本番接続確認、本人認証、送信権、APIの認可境界として使えない。本番監視結果を改変した入力でも許可は出ない。診断の実行を理由に完了済みの実メール試験や本番監視SELECTを再実行する必要はない。

```sh
node scripts/check-cargo-production-trial-preflight.cjs < /tmp/cargo-production-monitor-snapshot.json
```

入力には既存形式の `schema_version`、`scope=production-cargo-prelaunch-hold`、`observed_at`、`control`、`mail_budget` を使う。診断は監視の全項目を再検査せず、受付OFF、保護有効、メール無効、時間/日単位の送信試行0を確認する。時刻は5分以内かつ未来へ1分以内という既存監視と同じ読取基準を使う。これは試験の許可時間・送信上限の設定ではない。

## 将来の実装に必要な条件

| 境界 | 必要な条件と拒否する例 |
| --- | --- |
| 本人の認証 | サーバーが現在のログインを検証し、確認済みメールと運営者所属を照合する。ブラウザーのアカウントID、編集可能なユーザー情報、Originだけでは許可しない。DBへ渡す本人IDは将来APIで認証した結果に限る |
| 宛先 | 現在の本番本人アカウントに紐づく確認済みメールだけをサーバーが選ぶ。任意宛先・別本人・メール変更後の不一致を拒否する。私的なメールやユーザーIDをGitへ記入せず、検証環境の実値をコピーしない |
| 固定案件 | サーバー固定の架空案件1件へ試験ID・送信試行ID・下書き・依頼・見積もり・回答を結び付ける。別案件・別見積もり・付け替えを全段階で拒否する。実在する依頼人や詳細住所を使わない |
| 一度だけの開始 | 無効/条件未確定なら開始不可。開始は送信と別操作にし、一度使った台帳は終了・失効・失敗後も再開、複製、期限延長、件数リセットを許可しない。未承認の時間・上限をコードで補わない |
| 送信権の確保 | DBの行ロック等で試験全体と種別ごとの上限を原子的に確保する。並行呼出し、二重クリック、時間/日付の境界でも増えない。一般顧客用の時間/日単位の枠だけで試験全体の上限を代替しない |
| 外部送信の直前 | 本人・案件・期限・停止と、一回限りのdispatch権を再確認する。停止後や期限後は新たなdispatchを拒否する。直前権の確保と外部送信の間には取り消せない競合区間があるため、停止は以後の権利を閉じ、すでに送信中のものを照合対象として残す |
| 結果の確定 | stop/期限切れ後もすでに確保した送信の結果確定だけは可能にする。失敗・タイムアウト・結果不明でも枠を返さず、自動再送しない。結果不明は成功扱いにせず、台帳の試行証跡を下書き削除と連動して消さない |
| OTP・期限 | 既存OTPの期限と入力回数制限、下書き削除期限を弱めない。サーバー時刻で各操作を拒否でき、画面閉鎖や定期処理停止にも依存しない。見積もり期限は試験期限を越えず、現行の最短期限も満たす |
| リンクと本人 | 本番試験では秘密リンクのHMAC・期限・一回性に加えて本人ログインを要求する。リンクを知る他者、本人の別案件、ログアウト後の閲覧・回答を拒否する。秘密リンクをチャット・Git・ログへ出さない |
| 一般受付とメール停止 | 一般受付OFFを全期間維持する。現行のメール全体枠無効を変更せず使えるとは仮定しない。将来必要な専用停止・試験枠と設定差分を先に設計し、単なる一般受付ONや全体枠ONで代替しない |

既存の検証専用台帳は固定本人ID・30分・内部受付ON切替を含むため、本番へ流用しない。終了済みの検証枠も再開しない。現行OTP処理で下書きが削除される場合でも、将来の本番試験台帳は独立して失敗・不明の証跡と消費済み送信権を保持する必要がある。

## 通信なしで先に必要な検査

- 未認証、未確認メール、所属なし、別本人・宛先・案件・見積もり、期限不足、一般受付OFFの通常経路の拒否。
- 並行するclaimとdispatch、停止との競合、時間/日付の境界、二度目の開始、失効後・終了後の再開の拒否。
- 外部送信失敗・結果不明・処理中停止・期限切れ後の結果確定で、枠を返さず再送せず証跡を保持すること。
- 本人認証と秘密リンクの片方だけでは閲覧・回答できず、一度の回答が契約・配車・決済を作らないこと。

今回はその実行経路やDB台帳を追加していない。専用テストはローカル診断の停止判定、値の推測なし、入力不良の拒否、出力の秘匿、常時実行不可を確認する。完全な認可・並行性・送信停止の検査済みとは扱わない。

## 残る判断と次の実装

本人アカウント・架空案件と見積条件・試験日時/時間/送信上限・停止照合担当を運営者が確定する必要がある。その前にも、上記の境界を満たす独立台帳と隔離DBでの競合試験は設計できる。API/RPCへの接続と限定配備は別レビューとし、今の一般受付OFF・メール無効を維持する。実試験の実施には対象・変更設定・具体的な操作をそろえた別の確認が必要である。
